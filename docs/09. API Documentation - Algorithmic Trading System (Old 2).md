# **Nautilus Trader API Documentation**

Version: 2.0  
Last Updated: August 6, 2025

## **1.0 Introduction**

Welcome to the Nautilus Trader API documentation. This document provides a comprehensive guide for developers to interact with the Nautilus Trader platform programmatically. Our API-first design exposes the full power of the system, from managing trading strategies and executing orders to accessing real-time market data and leveraging our advanced Agentic AI Assistant.

The Nautilus Trader platform offers a multi-protocol API to cater to different use cases:

* **REST API:** For standard, request-response interactions like managing resources (strategies, accounts) and placing orders.  
* **GraphQL API:** For flexible, complex queries and fetching precisely the data you need, ideal for building rich user interfaces.  
* **WebSocket API:** For high-performance, bidirectional, real-time data streaming of market data and account updates.  
* **gRPC API:** For high-performance, low-latency internal communication between services (primarily for advanced users building integrations within the ecosystem).

## **2.0 Getting Started**

### **2.1 Base URLs**

* **Production:** https://api.nautilistrader.com/v1  
* **Staging/Paper Trading:** https://api.staging.nautilistrader.com/v1

### **2.2 Authentication**

The Nautilus Trader API uses the **OAuth 2.0** protocol for authentication. All requests must be authenticated by including a **JSON Web Token (JWT)** in the Authorization header.

**Header Format:** Authorization: Bearer \<YOUR\_JWT\_TOKEN\>

To obtain a JWT, your application must complete the OAuth 2.0 authorization code flow. API keys are also available for service-to-service authentication and can be managed through the user dashboard.

### **2.3 Rate Limiting**

To ensure system stability and fair usage, the API enforces rate limiting. The limits are applied per user, based on their subscription tier.

* **Standard Tier:** 10,000 requests per hour.  
* **Professional Tier:** 30,000 requests per hour.

Responses will include the following headers to help you track your usage:

* X-RateLimit-Limit: The total number of requests allowed in the current window.  
* X-RateLimit-Remaining: The number of requests remaining in the current window.  
* X-RateLimit-Reset: The UTC epoch timestamp when the rate limit window resets.

If you exceed the rate limit, you will receive an **HTTP 429 Too Many Requests** response.

### **2.4 Error Handling**

The API uses standard HTTP status codes to indicate the success or failure of a request. The response body for an error will contain a JSON object with more details.

**Error Response Format:**

{  
  "error": {  
    "code": "invalid\_parameter",  
    "message": "The 'symbol' parameter is missing or invalid.",  
    "request\_id": "a1b2c3d4-e5f6-7890-1234-567890abcdef"  
  }  
}

**Common HTTP Status Codes:**

* 200 OK: The request was successful.  
* 201 Created: The resource was successfully created.  
* 400 Bad Request: The request was malformed (e.g., missing parameters).  
* 401 Unauthorized: Authentication failed or was not provided.  
* 403 Forbidden: The authenticated user does not have permission to perform the action.  
* 404 Not Found: The requested resource does not exist.  
* 429 Too Many Requests: The rate limit has been exceeded.  
* 500 Internal Server Error: An unexpected error occurred on our end.

## **3.0 REST API Reference**

This section details the endpoints available through our REST API, built on **FastAPI**.

### **3.1 Orders**

#### **POST /orders**

Place a new order for a specified account.

* **Request Body:**  
  {  
    "account\_id": "acc\_123456789",  
    "symbol": "AAPL",  
    "side": "buy",  
    "type": "limit",  
    "quantity": 100,  
    "limit\_price": 150.00,  
    "time\_in\_force": "day"  
  }

* **Parameters:**  
  * account\_id (string, required): The ID of the account to place the order on.  
  * symbol (string, required): The ticker symbol for the instrument.  
  * side (string, required): buy or sell.  
  * type (string, required): market, limit, stop, stop\_limit.  
  * quantity (number, required): The number of shares/contracts to trade.  
  * limit\_price (number, optional): Required for limit and stop\_limit orders.  
  * stop\_price (number, optional): Required for stop and stop\_limit orders.  
  * time\_in\_force (string, optional): day, gtc, ioc, fok. Defaults to day.  
* **Success Response (201 Created):**  
  {  
    "order\_id": "ord\_abcdef12345",  
    "status": "pending\_new",  
    "created\_at": "2025-08-06T15:30:00Z"  
  }

#### **GET /orders/{order\_id}**

Retrieve the status of a specific order.

* **Path Parameters:**  
  * order\_id (string, required): The ID of the order to retrieve.  
* **Success Response (200 OK):**  
  {  
    "order\_id": "ord\_abcdef12345",  
    "symbol": "AAPL",  
    "side": "buy",  
    "type": "limit",  
    "quantity": 100,  
    "filled\_quantity": 50,  
    "status": "partially\_filled",  
    "limit\_price": 150.00,  
    "created\_at": "2025-08-06T15:30:00Z",  
    "updated\_at": "2025-08-06T15:31:00Z"  
  }

#### **DELETE /orders/{order\_id}**

Cancel an open order.

* **Path Parameters:**  
  * order\_id (string, required): The ID of the order to cancel.  
* **Success Response (200 OK):**  
  {  
    "order\_id": "ord\_abcdef12345",  
    "status": "pending\_cancel"  
  }

### **3.2 Portfolio**

#### **GET /portfolio**

Retrieve the current state of the user's portfolio, aggregated across all linked broker accounts.

* **Success Response (200 OK):**  
  {  
    "total\_value": 125000.00,  
    "cash": 25000.00,  
    "positions": \[  
      {  
        "symbol": "AAPL",  
        "quantity": 100,  
        "market\_value": 15200.00,  
        "unrealized\_pnl": 200.00  
      },  
      {  
        "symbol": "GOOGL",  
        "quantity": 50,  
        "market\_value": 84800.00,  
        "unrealized\_pnl": \-1200.00  
      }  
    \]  
  }

### **3.3 Strategies**

#### **POST /strategies**

Create or update a trading strategy.

* **Request Body:**  
  {  
    "name": "My EMA Crossover Strategy",  
    "description": "A simple strategy that buys when the 10-day EMA crosses above the 30-day EMA.",  
    "code\_body": "import nautilus\_trader as nt\\n\\nclass MyStrategy(nt.Strategy):\\n    \# ... strategy code ...",  
    "language": "python"  
  }

* **Success Response (201 Created):**  
  {  
    "strategy\_id": "strat\_xyz789",  
    "name": "My EMA Crossover Strategy",  
    "version": 1,  
    "created\_at": "2025-08-06T16:00:00Z"  
  }

#### **POST /strategies/{strategy\_id}/backtest**

Run a backtest for a specific strategy.

* **Path Parameters:**  
  * strategy\_id (string, required): The ID of the strategy to backtest.  
* **Request Body:**  
  {  
    "start\_date": "2023-01-01",  
    "end\_date": "2024-01-01",  
    "symbols": \["AAPL", "MSFT"\]  
  }

* Success Response (202 Accepted):  
  The backtest is initiated as an asynchronous job.  
  {  
    "backtest\_id": "bkt\_1a2b3c",  
    "status": "started"  
  }

## **4.0 GraphQL API Reference**

Our GraphQL API provides a flexible interface for querying complex data structures, ideal for powering dynamic user interfaces.

**Endpoint:** https://api.nautilistrader.com/v1/graphql

### **4.1 Example Query**

Retrieve dashboard data, including portfolio summary and watchlist prices.

query GetDashboard {  
  portfolio {  
    totalValue  
    cash  
    unrealizedPnl  
  }  
  positions {  
    symbol  
    quantity  
    marketValue  
  }  
  watchlist(symbols: \["BTC-USD", "ETH-USD"\]) {  
    symbol  
    lastPrice  
    changePercent24h  
  }  
}

### **4.2 Example Subscription**

Subscribe to real-time updates for an order's status.

subscription OnOrderStatusChanged($orderId: ID\!) {  
  orderStatusUpdate(orderId: $orderId) {  
    orderId  
    status  
    filledQuantity  
    avgFillPrice  
  }  
}

## **5.0 WebSocket API Reference**

The WebSocket API is the primary method for receiving real-time, low-latency data from the platform.

**Endpoint:** wss://ws.nautilistrader.com

### **5.1 Connection and Authentication**

To connect, establish a WebSocket connection to the endpoint. Once connected, you must send an authentication message within 5 seconds.

**Authentication Message:**

{  
  "action": "auth",  
  "key": "\<YOUR\_API\_KEY\>"  
}

### **5.2 Subscribing to Channels**

After authenticating, you can subscribe to one or more channels.

**Subscription Message:**

{  
  "action": "subscribe",  
  "channels": \["marketdata:AAPL", "portfolio:acc\_123456789"\]  
}

### **5.3 Channels and Data Formats**

#### **marketdata:{symbol}**

Streams real-time trade and quote data for a given symbol.

* **Data Format (Trade):**  
  {  
    "channel": "marketdata:AAPL",  
    "type": "trade",  
    "timestamp": 1672531200000,  
    "price": 150.25,  
    "volume": 100  
  }

* **Data Format (Quote):**  
  {  
    "channel": "marketdata:AAPL",  
    "type": "quote",  
    "timestamp": 1672531200500,  
    "bid\_price": 150.24,  
    "ask\_price": 150.26,  
    "bid\_size": 500,  
    "ask\_size": 300  
  }

#### **portfolio:{account\_id}**

Streams real-time updates to an account's portfolio, including position changes and P\&L.

* **Data Format:**  
  {  
    "channel": "portfolio:acc\_123456789",  
    "type": "position\_update",  
    "timestamp": 1672531201000,  
    "symbol": "AAPL",  
    "quantity": 150,  
    "market\_value": 22537.50,  
    "unrealized\_pnl": 337.50  
  }

#### **orders:{account\_id}**

Streams real-time updates for all orders in a given account.

* **Data Format:**  
  {  
    "channel": "orders:acc\_123456789",  
    "type": "order\_update",  
    "timestamp": 1672531202000,  
    "order\_id": "ord\_abcdef12345",  
    "status": "filled",  
    "filled\_quantity": 100,  
    "avg\_fill\_price": 150.25  
  }
