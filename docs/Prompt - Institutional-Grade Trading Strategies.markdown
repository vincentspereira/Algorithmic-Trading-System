**The 5-Pillar Strategy Architecture (Mandatory)**

Every strategy you build is not just a set of entry/exit rules. It MUST be a complete, self-contained trading system encapsulated in a Python class that inherits from a BaseInstitutionalStrategy. This class must implement the following five pillars, using the features from our existing technical indicators and candlestick patterns library.

- **Pillar 1: Signal Generation & Augmentation:**
  - **Action:** Implement the core logic of the strategy using our library of volume-weighted, adaptive, and multi-timeframe indicators and patterns. Include multi-timeframe confirmation (e.g., align daily and hourly signals).
  - **Output:** The signal generation method must not just return "buy" or "sell." It must return a rich IndicatorSignal object containing the raw value, signal type, and a dynamic composite confidence score as generated by our indicators , timeframe, and strength (0-1 based on aggregation of multiple signals).
- **Pillar 2: Dynamic Risk & Money Management:**
  - **Action:** Every strategy must have a complete, dynamic risk management module that considers portfolio-level correlations and volatility.
  - **Features:**
    - **Position Sizing:** Must be calculated automatically based on a configurable account risk percentage and the instrument's real-time volatility (using our Normalized ATR), and correlation to existing positions.
    - **Stop-Loss:** Must have a clearly defined initial stop-loss (e.g., based on ATR or candlestick lows) with portfolio-wide max drawdown checks.
    - **Trailing Stop-Loss:** Must implement a dynamic trailing stop-loss (e.g., Chandelier Exit) to protect profits while letting them run.
    - **Take-Profit:** Must have one or more take-profit levels, potentially based on key support/resistance levels or a fixed risk-reward ratio (e.g., 1:2).
- **Pillar 3: Market Regime Adaptation:**
  - **Action:** Strategies must not trade in all conditions. They must be context-aware. They must use our Market Structure Indicators (e.g., Choppy Market Index, ADX, long-term VWMA) and optional ML clustering (e.g., with PyOD) to determine the current market regime.
  - **Logic:** The strategy must automatically disable itself or reduce its position size when the market regime is unfavourable for its specific logic (e.g., a mean-reversion strategy should be disabled in a strong trending market). Validate regimes during backtesting to avoid overfitting.
- **Pillar 4: Execution & Order Management:**
  - **Action:** The strategy's logic must be decoupled from the act of execution.
  - **Output:** Instead of generating a raw order, the strategy should produce a desired action / high-level "Execution Intent" object (e.g., {'action': 'ENTER_LONG', 'algorithm': 'VWAP', 'urgency': 'MEDIUM' , 'time_in_force': 'GTC'}). This allows our sophisticated Order Management System to handle the execution using the appropriate algorithm (TWAP/VWAP, etc.) , incorporating slippage modeling for realism.
- **Pillar 5: Performance Tracking & Optimization:**
  - **Action:** Every strategy must be designed for analysis and optimization.
  - **Features:**
    - The strategy must log all its key performance metrics (e.g., win rate, profit factor, drawdown , Sharpe ratio, Sortino ratio, Calmar ratio) to our analytics database.
    - All of the strategy's parameters (e.g., indicator periods, risk settings) must be exposed / externalized into a separate config.json file to allow for easy customization and optimization via our **Optuna** integration.
    - Include a method to export metrics for backtesting validation and compliance auditing.
