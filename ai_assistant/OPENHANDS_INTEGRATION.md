# OpenHands Integration Documentation

## Overview

The AI Assistant now includes OpenHands integration as a powerful code development tool. This integration enables the AI assistant to modify code on the file system using a structured planning and execution workflow.

## Features

### Core Capabilities
- **Natural Language Code Development**: Accept development requests in plain English
- **Intelligent Task Planning**: Break down complex requests into manageable steps
- **Safe Code Execution**: File system operations with comprehensive safety checks
- **Automatic Backups**: Create backups before any file modifications
- **Rollback Support**: Ability to undo changes if something goes wrong
- **Preview Mode**: See what would be done without making actual changes

### Supported Development Tasks
- Adding new API endpoints
- Creating new functions and classes
- Modifying existing code
- Creating new files with proper structure
- Refactoring code
- Adding tests and documentation
- Fixing bugs and issues
- Updating configuration files

## Architecture

### Key Components

#### 1. Configuration Classes
- **`OpenHandsConfig`**: Main configuration for workspace settings, safety limits, and backup management
- **`TaskType`**: Enumeration of supported development task types
- **`TaskPriority`**: Priority levels for task execution

#### 2. Workflow Management
- **`PlanningStep`**: Represents individual steps in the development workflow
- **`ExecutionResult`**: Contains results and metadata from step execution
- **`OpenHandsWorkflow`**: Complete workflow state and tracking

#### 3. Safety Features
- **Path Validation**: Ensures all operations stay within the workspace
- **File Extension Filtering**: Only allows modifications to approved file types
- **Size Limits**: Prevents operations on files that are too large
- **Backup System**: Automatic backup creation with cleanup management

## Usage Examples

### Example 1: Adding a New API Endpoint

**Request:**
```
"Add a new endpoint /status to the AI assistant"
```

**What OpenHands Does:**
1. **Planning Phase:**
   - Analyze existing API structure
   - Plan endpoint implementation
   - Plan documentation updates

2. **Execution Phase:**
   - Create backup of main.py
   - Generate endpoint code
   - Insert endpoint into main.py
   - Update documentation

**Generated Code:**
```python
# Status endpoint - Generated by OpenHands
@app.get("/api/v1/status", tags=["Status"])
async def get_status():
    """
    Status endpoint
    Generated based on request: Add a new endpoint /status to the AI assistant
    """
    return {
        "status": "active",
        "timestamp": datetime.utcnow().isoformat(),
        "message": "Status endpoint is working"
    }
```

## Safety and Security

### File System Protection
- **Workspace Boundaries**: All operations restricted to the configured workspace
- **Forbidden Paths**: Automatic blocking of sensitive directories (.git, __pycache__, etc.)
- **Extension Whitelist**: Only approved file extensions can be modified
- **Size Limits**: Files larger than 1MB are protected by default

### Backup and Recovery
- **Automatic Backups**: Every file modification creates a timestamped backup
- **Backup Cleanup**: Old backups automatically removed to prevent storage bloat
- **Rollback Capability**: Complete workflow rollback available if issues occur
- **Audit Trail**: All operations logged for security and debugging

### Configuration Options
```python
# Environment variables for customization
WORKSPACE_ROOT=/path/to/workspace
OPENHANDS_BACKUP_DIR=backups/openhands
MAX_FILE_SIZE=1048576  # 1MB
MAX_BACKUP_FILES=50
ENABLE_ROLLBACK=true
DRY_RUN_MODE=false  # Global preview mode
```

## API Integration

### Tool Definition
The `code_development_tool` is integrated as a LangChain tool with the following signature:

```python
@tool("code_development_tool", args_schema=CodeDevelopmentInput)
def code_development_tool(
    request: str, 
    preview_only: bool = False, 
    target_files: Optional[List[str]] = None
) -> str:
```

### Input Parameters
- **`request`**: Natural language development request
- **`preview_only`**: Boolean flag for dry-run mode
- **`target_files`**: Optional list of specific files to target

### Response Format
The tool returns a comprehensive formatted string containing:
- Workflow ID for tracking
- Task type and priority analysis
- Step-by-step planning breakdown
- Execution results with timing
- File modification summary
- Safety information and next steps

## Error Handling

### Comprehensive Error Management
- **Validation Errors**: Invalid file paths, unsupported extensions
- **Execution Errors**: File system issues, permission problems
- **Dependency Errors**: Missing dependencies between planning steps
- **Rollback Errors**: Issues during workflow rollback

### Error Response Format
```
❌ Error in code development tool: [Detailed error message]

Please check the request format and try again. For complex requests, 
consider breaking them into smaller, more specific tasks.
```

## Best Practices

### For Users
1. **Be Specific**: Provide clear, detailed development requests
2. **Use Preview Mode**: Test complex changes with `preview_only=True` first
3. **Review Changes**: Always review generated code before deployment
4. **Test Thoroughly**: Run tests after any code modifications
5. **Backup Important Work**: While OpenHands creates backups, maintain your own as well

### For Developers
1. **Extend Task Types**: Add new `TaskType` enums for specialized operations
2. **Customize Safety Rules**: Adjust file extension and path restrictions as needed
3. **Monitor Logs**: Review OpenHands operation logs for debugging
4. **Update Templates**: Modify code generation templates for your coding standards

## Troubleshooting

### Common Issues

#### "Unsafe file path" Error
- **Cause**: Attempting to modify files outside the workspace or in forbidden directories
- **Solution**: Ensure all target files are within the configured workspace

#### "File extension not allowed" Error
- **Cause**: Trying to modify files with unsupported extensions
- **Solution**: Add the extension to `allowed_extensions` in OpenHandsConfig

#### "Could not create a valid execution plan" Error
- **Cause**: Request too vague or unsupported task type
- **Solution**: Provide more specific details or break into smaller tasks

#### Rollback Issues
- **Cause**: Backup files missing or corrupted
- **Solution**: Check backup directory and permissions
